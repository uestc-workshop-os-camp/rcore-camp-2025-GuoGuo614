## 问答题
1. 程序报错如下：
[kernel] PageFault in application, bad addr = 0x0, bad instruction = 0x804003a4, kernel killed it.
[kernel] IllegalInstruction in application, kernel killed it.
[kernel] IllegalInstruction in application, kernel killed it.
  - 第一个程序是触发了页错误，也就是非法的内存访问。
  - 后两个程序，内核的表现是检测到了非法指令，故终止了应用。
2. 刚进入__restore时，sp指向的是内核栈，也就是由__alltraps 设置的，用户程序Trap上下文所在的地方，因此进行了寄存器的恢复。
  - 场景一：在Trap（系统调用、异常或中断）之后恢复到用户态，继续运行用户程序，故需要恢复Trap上下文。
  - 场景二：内核需要切换任务，因此调整sp指向另一个任务的内核栈，恢复上下文后即完成了任务切换。
3. sstatus寄存器：对于进入用户态的作用是恢复特权级相关的状态，确保返回用户态时环境与 Trap 发生前一致。比如设置U模式等。
  - spec寄存器：恢复了Trap之前的PC，决定了返回用户态之后从其哪一条指令开始执行。
  - sscratch寄存器：在Trap期间临时保存用户栈指针，在返回用户态后则重新设置为内核态指针，方便下次Trap时正确切换栈。
4. x2寄存器是sp，此时sp已经指向内核栈，完成上下文的恢复，不应该被破坏，在最后返回内核态时再从sscratch完成sp的恢复；关于x4也就是tp，不太了解，查了一下资料：
  - tp是线程指针
    - 在大多数应用场景下，用户程序不会用tp，或者tp由运行时环境（如线程库）管理，内核不需要关心它的值。
5. 上文已经回答过。
6. 发生在最后一条指令sret，gdb一波会发现，sret指令会根据sstatus的值和sepc的值来修改CPU的状态和PC，从而返回指定的地址继续执行用户程序。
```
# 下一步是 sret
(gdb) p/x $sstatus
$1 = 0x200000000
(gdb) p/x $sepc
$2 = 0x80400000
(gdb) p/x $pc
$3 = 0x8020154e
(gdb) si
0x0000000080400000 in ?? ()
(gdb) p/x $sstatus
$4 = 0x200000020
(gdb) p/x $pc
$5 = 0x80400000
```
7. 上文已经回答过。
8. 并不是trap.S里面的指令完成这件事，在__alltraps之前就发生了，是ecall这条指令。
